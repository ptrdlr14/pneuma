# π₀.₅（pi05）

[返回 README](../README.md) · [接入指南](usage.md) · [协议说明](protocol.md)

Pneuma 用 Burn 原生执行 π₀.₅：SigLIP-So400m 视觉塔、PaliGemma-2B 语言前缀、
Gemma-300M 动作专家（adaRMS 时间调制）与 10 步 Euler flow matching。
运行时不需要 Python，也不隐式联网。

## 权重

从 ModelScope 下载。`lerobot/pi05_libero` 的 processor JSON 没有归一化统计，
不能直接推理；`lerobot/pi05_libero_finetuned_v044` 带统计文件，可直接转换。

```sh
MS=/home/luyawang/.local/share/mise/installs/pipx-modelscope/latest/bin/modelscope
$MS download --repo-type model lerobot/pi05_libero_finetuned_v044 \
  --local-dir /data/nvme1/modelscope/lerobot/pi05_libero_finetuned_v044
```

PaliGemma 分词器需要单独下载（权重文件里没有）：

```sh
$MS download --repo-type model google/paligemma-3b-pt-224 \
  config.json tokenizer.json tokenizer_config.json \
  --local-dir /data/nvme1/modelscope/paligemma-tokenizer
```

## 转换与启动

```sh
cargo run --release -- convert --from=lerobot --to=pneuma \
  --input=/data/nvme1/modelscope/lerobot/pi05_libero_finetuned_v044 \
  --vlm-path=/data/nvme1/modelscope/paligemma-tokenizer \
  --output=outputs/pi05-native

cargo run --release -- serve --config=examples/pi05_libero.toml \
  --checkpoint=outputs/pi05-native --device=cuda:0
```

转换把 tokenizer 资源写入产物的 `vlm/`，服务只加载原生 `.bpk` checkpoint。
BF16 源权重在导入时统一转为 F32。

## 输入契约

以下数字来自 `lerobot/pi05_libero_finetuned_v044` 的 `config.json`：

| 项 | 值 |
|---|---|
| 相机 | `observation.images.image`、`observation.images.image2`，HWC uint8 256×256 |
| 状态 | `observation.state`，8 维 float32，按 MEAN_STD 归一化 |
| 动作 | `action`，7 维 float32，按 MEAN_STD 反归一化 |
| 动作块 | `chunk_size=50`，`n_action_steps=50` |
| 图像输入 | 内部 resize 到 224×224 并映射到 `[-1,1]` |

checkpoint 还可能声明 `observation.images.empty_camera_0`。它的注意力 mask 恒为 0，
Pneuma 直接省略，不要求客户端发送。

### 提示词

状态先归一化到 `[-1,1]`，再离散化为 256 个桶，拼进提示词：

```
Task: {task}, State: {s0 s1 ...};\nAction: 
```

任务文本中的下划线和换行被替换为空格，与官方
`Pi05PrepareStateTokenizerProcessorStep` 一致。分词长度固定 200，右 padding。

## 支持范围

- 只支持 `paligemma_variant=gemma_2b` 与 `action_expert_variant=gemma_300m`。
- 单步观测、单次预测；`empty_cameras` 允许，但推理时省略。
- 归一化支持 `MEAN_STD`、`MIN_MAX`、`QUANTILES`（q01/q99）与 `QUANTILE10`（q10/q90）。
- 不支持 RTC、相对动作、历史观测记忆（`use_visual_memory` / `use_proprioceptive_memory`）。

## 数值验证状态

已在 server1 用 `lerobot/pi05_libero_finetuned_v044` 完成端到端验证（2026-11-03）：

- 转换：811 个参数应用成功，1 个未使用（专家 `lm_head`）保存到 `interop/extra.bpk`；产物 `model.bpk` 13 GB。
- 推理：`cuda:0` 上加载 13 GB record 并完成一次 10 步采样，约 21.6 秒；动作形状
  `[1,50,32]`，全部有限。
- 逐值对齐：`scripts/dump_pi05_reference.py` 在 server1 的 CPU/F32 环境生成参照，
  ignored 测试 `pi05_matches_official_reference` 比较，全部通过。

| 张量 | 最大绝对误差 | 平均绝对误差 |
|---|---:|---:|
| 归一化状态 | 0 | 0 |
| 预处理图像 | 4.8e-7 | 2e-8 |
| token 与 attention mask | 0 | 0 |
| 语言嵌入 | 0 | 0 |
| 视觉前缀嵌入 | 6.4e-2 | 7.8e-4 |
| 动作（10 步） | 9.8e-3 | 2.7e-4 |

视觉前缀误差大于语言部分，原因是官方实现先把整个模型转成 bf16，再把视觉塔、投影层和范数
转回 f32（见 `to_bfloat16_for_selected_params`）。视觉权重因此被 bf16 取整；Pneuma 保留
checkpoint 的 F32 原值，所以与参照相差约 0.4%。这是精度选择差异，不是结构差异。

复现脚本在 `scripts/dump_pi05_reference.py`，Rust 侧对应 ignored 测试
`pi05_native_checkpoint_predicts_finite_actions`。在具备 LeRobot 的环境中：

```sh
/path/to/python -I scripts/dump_pi05_reference.py \
  --checkpoint=/path/to/pi05_libero_finetuned_v044 \
  --vlm-path=/path/to/paligemma-tokenizer \
  --lerobot-src=/path/to/lerobot/src \
  --output=outputs/pi05-parity
```

在拿不到对齐结果前，不宣称 Pneuma 的 π₀.₅ 数值与官方一致。
